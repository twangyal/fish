# Development Process

## Non-Trivial Changes

Use:

Architect → Builder → Reviewer → Verifier → Lead

## Features

Use Superpowers:

brainstorming → writing-plans → implementation workflow

Do not implement before the design has been approved.

## Bugs

Use:

systematic-debugging → root cause → regression test → minimal fix → review → verification

## Worktrees

Use Superpowers `using-git-worktrees` when isolated implementation work is required.

## Plans

Store approved implementation plans under:

`docs/superpowers/plans/`

## Specs

Store approved design specifications under:

`docs/superpowers/specs/`

## Commits

Prefer small coherent commits aligned with independently reviewable tasks.
